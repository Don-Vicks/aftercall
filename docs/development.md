# Develop and check

How to run every part of Aftercall locally, and what each check shows.

## Checks and what you'll see


| Do | See |
| --- | --- |
| `pnpm install && pnpm verify --quick` | Typecheck of every package, 367 core, 36 backend and 20 MCP server tests (more with `DATABASE_URL` set, adding the Postgres runs; the MCP tests build the one-file server first and run it with plain `node`), the web build, the NEAR signer, the desktop Rust tests (recorder with the mic-silent, mic-stopped and "Call ended?" watches, the ⌘⇧R press gate, encryption at rest, agents read-only by default and their activity list, action item edits, TDX quote verification, recovery, the audio sweep) and the contract's unit tests, with a pass/fail summary. `pnpm verify` adds the contract running on a local NEAR node (20 more tests, about 8 minutes; needs `cargo-near` and the `wasm32-unknown-unknown` target). Needs Node 24, pnpm 10 and stable Rust. The desktop Rust tests build only on macOS (Core Audio, WebKit); on Linux, verify builds the desktop web app and MCP bundle and lists the Rust tests as skipped. |
| `pnpm dev:ui`, open http://localhost:1420 | The Mac app's interface in a browser on a sample meeting: Today, the ⌘K palette, the meeting with your notes, ticks and approve-with-undo, the transcript as a conversation, People, Ask your meetings (⌘J), Action items (the pencil on a row edits its text, owner or due date; an edited item shows "edited" and offers Restore original), the $5,000 payment the contract blocks, Coding agents with sample activity. Recording is simulated in the browser: New recording shows the live page, the floating pill, your notes (⌘⇧R) and processing in run order; `/live.html` shows the floating recorder, and `?simulate=silent`, `?simulate=mic-silent`, `?simulate=mic-stopped` and `?simulate=call-ended` show the call and mic warnings and the "Call ended?" prompt 3 s into a recording. |
| `pnpm --filter @aftercall/web dev`, open http://localhost:3000 | The landing page, How it works (the journey of one meeting and every check) and Install (`/download`: the unsigned test build for NEAR testnet, its one-line Terminal install and the Gatekeeper steps; live at https://getaftercall.vercel.app/download, with the browser demo at https://getaftercall.vercel.app/demo), plus `/verify`, which re-runs a proof link's checks in your browser, and `/handling`, How a call is handled: each step a call goes through, what each line of the recap footer means, what isn't proven, and the open NEAR AI issues Aftercall's checks don't close. |
| `pnpm sample:notes` (needs `NEAR_AI_API_KEY` in `.env`) | One of the two fictional sample calls in [`samples/`](../samples) goes through the real pipeline on NEAR AI Cloud: every attestation check below, Whisper on both stems, the transcript end-to-end encrypted to the attested Qwen TEE, the strict-schema summary and the signature check. It prints the notes (including a 40 USDC deposit to the designer, with its quote), ✓/✗ for every check, grouped Gateway / Whisper TEE / Qwen TEE / Response, and the estimated cost: typically well under a cent per sample at NEAR AI's prices on 1 Nov 2026, with the summary capped at 12,288 output tokens. `pnpm sample:notes all` runs both and adds a total. It exits 0 when every sample came back verified and 1 otherwise. Without a key it stops before sending anything. |
| In the Mac app: Home → "Open a sample recording", then Make notes | The same sample becomes an ordinary recording labelled Sample, processed with your NEAR AI key; the Verify sheet lists every check. In `pnpm dev:ui` it opens with its script. |
| `pnpm --filter @aftercall/web dev`, open http://localhost:3000/verify | The public Verify page. With a proof link (`/verify#…`, copied from the app's Verify sheet) it reads the proof from NEAR and re-runs every check in your browser. |
| Read [`docs/agents-demo.md`](agents-demo.md), or run `pnpm --filter @aftercall/mcp build && node apps/mcp/scripts/demo.ts` and the `claude` command it prints | Claude Code 2.1.314 on the MCP server the app ships, recorded on 1 Nov 2026: read-only, it lists meetings and doesn't claim; after the switch, it claims an item. The other end of the socket is the server's test stand-in for the app (same protocol and rules, two sample meetings), not the Mac app. |
| Read [`contracts/agent-wallet/src/lib.rs`](../contracts/agent-wallet/src/lib.rs) and [`tests/sandbox.rs`](../contracts/agent-wallet/tests/sandbox.rs) | Why the app can't overspend: its key can call only `pay` and `record_proof`, every rule change needs 1 yoctoNEAR (which a limited key can't attach), over-cap payments park until the owner's own wallet approves, payments to other chains are off until the owner sets a cap for them, and every user pays for their own storage. Each claim has a test on a real local NEAR node. |
| Read [`packages/core/src/notes/`](../packages/core/src/notes) | The notes pipeline: two audio stems become one transcript, the model's output must match a strict schema, any item without an exact quote from the transcript is dropped (listed on the meeting page under "N items dropped", never acted on, and counted in the proof), amounts are read from the spoken words (never from the model's number) and kept only when the same value is in the quote, and every reply's signature must recover to the attested enclave. Long calls are written up in parts (`sections.ts`) and merged, with every quote still checked against the whole transcript. The same request also asks the model who is speaking on the call's side when the transcript makes it clear; those names are kept as "likely", never checked like quotes. Meetings can be in any language: the notes are written in English and every quote is copied in the language spoken, then checked against the transcript the same way. |


## Run it


Needs Node 24, pnpm 10, Rust stable. Postgres for claim links (`DATABASE_URL`; kept in memory otherwise).

```bash
pnpm install
./scripts/dev.sh   # backend (Postgres), web pages and the Mac app together
pnpm dev:ui        # the interface in a browser at http://localhost:1420
pnpm verify        # every check
```

macOS grants system-audio capture only to a bundled app, so to record, build it with `pnpm --filter @aftercall/desktop tauri build --debug --bundles app` and open the `.app`. The first run walks through an audio check and the NEAR AI key; Settings → Set up payments connects NEAR in three stages, shown as a rail at the top of the sheet: your account, this Mac's key, and one approval in your wallet. The account is made for you on testnet by default (a suggested name, checked free on NEAR; "I already have an account" takes yours instead, and testnet uses Aftercall's contract, `wallet.aftercall.testnet`, built into `packages/core/src/network.ts` and `crates/near-tx`; Advanced takes your own deployment). Each recovery phrase (the new account's, and Aftercall's own for this Mac's key) is shown once with a small picture of which of the two it is; Save recovery kit is the main way on (a plain-text kit wherever you pick in the macOS Save dialog, readable only by you, refused inside Aftercall's own folders: `recovery_kit.rs`; a folder that syncs to the cloud gets a warning), or write the words down; Copy (cleared after 60 s if the clipboard still holds the words) and Print sit on the words. Three words typed back follow either way, and Aftercall keeps neither phrase (the Save dialog, clipboard and print panel for a kit have so far run only in the browser preview; the Rust writer is tested). Then one signing request (`setup` in `packages/core/src/wallet/actions.ts`) asks your wallet once for everything still missing: `register` and `set_cap` (a 25 USDC daily cap on testnet by default, editable first) as two actions of one transaction, the limited key for this Mac, and your account's USDC registration if it has none; Meteor's and Intear's NEAR Connect code hands the whole list to the wallet in one request (read 3 Nov 2026), and the contract's sandbox test `setup_registers_and_sets_the_cap_in_one_transaction` covers the batch. A new account goes into Meteor first, with the clicks shown on that step. A "Ready to pay" card then links Circle's USDC faucet (pick Near Testnet) and offers Deposit and Add payee. The batched approval hasn't yet been signed in a real wallet. That approval happens on the web `/sign` page, so run the web app too (`./scripts/dev.sh`, or `pnpm --filter @aftercall/web dev`); if it isn't answering, the app says so and offers the near-cli commands. Settings also sets autopilot. While Aftercall runs, ⌘⇧R works from any app: it brings Aftercall forward and opens the record sheet (pressed again with the box ticked, it starts recording), or your notes while recording. While you record, ⌘⇧M marks the moment from any app too: a tick on the live page's timeline and `[mm:ss]` in your notes, which becomes a jump to that line of the transcript; it's held only while recording and follows the same switch. The trade-off: while it's on, other apps can't use ⌘⇧R (Safari's Reader, for example), or ⌘⇧M during a recording. Settings → Shortcut turns it off, so ⌘⇧R works only inside Aftercall and other apps keep it; the choice is saved and takes effect at once (test `the_shortcut_works_from_any_app_until_you_turn_it_off` covers the saved choice; the switch itself hasn't been pressed in the Mac app). If another app already holds ⌘⇧R, the shortcut works only inside Aftercall, Settings says so, and onboarding and the live page say "in Aftercall" instead of "from any app". Deploy the contract to testnet with [`contracts/scripts/deploy-testnet.sh`](../contracts/README.md). Backend settings: `apps/backend/.env.example`.

| Part | Choice |
| --- | --- |
| Desktop | Tauri v2, React, TypeScript, Tailwind; Rust Core Audio process tap (`cidre`), `cpal` microphone |
| Shared core | TypeScript: notes pipeline, schema (zod), verification, owner actions, recap, autopilot, search |
| Backend | NestJS + Postgres: NEP-413 sign-in, Resend email, claim links |
| Web | Next.js: Verify, How a call is handled, sign and claim pages |
| Contract | Rust, near-sdk 5.29, cargo-near, near-workspaces sandbox tests; Circle USDC |

Repo layout: `apps/desktop`, `apps/backend`, `apps/web`, `apps/mcp`, `packages/core`, `packages/tokens` (design tokens as CSS for the web), `contracts/agent-wallet`, `crates/near-tx`, `scripts/`, `docs/` (rules, design source).
